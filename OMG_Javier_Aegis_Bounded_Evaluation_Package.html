Section 1

Executive Summary

OMG contains a genuine, fully-wired, three-stage workflow matching the requested pattern exactly: an Approved Agent already carrying a complete, verified "Governed" T0 state (confirmed both in source and live in production); a working Material Change mechanism (saveReassessmentTrigger) that measurably alters governance state; and a working Consequential Action mechanism (Kill Switch engagement) that measurably alters the asset's real operational status. Every mechanism cited below is quoted verbatim from the current codebase — none is proposed, none is aspirational.
What this package is not: the Material Change and Consequential Action stages for this specific asset have not yet been exercised — no ReassessmentTrigger or KillSwitchRecord currently exists for it. Both mechanisms are proven, real, and already exercised against other assets in the same tenant. Completing this package requires OMG's own team to exercise them once, honestly, before freezing anything for Aegis.

Section 7

T1 Governance State

Once a trigger is open, getReauthorisationForAsset (storageService.ts:4804-4817) reads it and computeReauthorisation (reauthorisationEngine.ts:31-72) returns at minimum outcome 'Reassess'. resolveGovernanceState (governanceStateResolutionLayer.ts:60-142) maps this to Unified Governance State Conditionally Governed at minimum — computed, traceable, reproducible from the same inputs every time.

The transition itself is recorded as a real GovernanceStateHistoryEntry (types/index.ts:2597-2606) by recordGovernanceStateIfChanged (storageService.ts:4874-4900), carrying previousState, newState, triggeringEvent, triggeringEngine, and a timestamp.

What OMG Represents

  • A complete, computed T0 governance state, sourced from real asset fields, not a status label alone.
  • A named, structured authority basis (Authority Provenance + Authority Currency), independently verifiable.
  • A structured, multi-dimensional evidence sufficiency verdict, not a presence check.
  • A real, working Material Change mechanism that measurably alters governance state.
  • A real, working Consequential Action mechanism (Kill Switch) that measurably alters operational status, gated by a named authority already on record.
  • A machine-recorded, timestamped history of every governance state transition, with its triggering cause and engine named.
Section 10

What OMG Does Not Represent

  • Aegis's own bounded authority/evidence reasoning — OMG supplies governed context; it does not perform or simulate Aegis's evaluation.
  • Any pre-existing Material Change or Consequential Action record for this specific asset — both require one honest, real exercise of the existing mechanism before this package can be frozen.
  • A workspace-scoped audit entry for reassessment filing — saveReassessmentTrigger never writes a WorkspaceAuditEntry despite 'Triggered Reassessment' existing as a defined action value (types/index.ts:2342) — a real, minor, pre-existing gap, stated as fact, not proposed as a fix.
  • Any external decisioning system integration — confirmed zero references to any such system anywhere in this codebase.
