Section 1

Executive Summary

OMG Release 20 introduced a governance interoperability capability that allows externally authorised governance positions — decisions made by an authority outside OMG — to be received, operationalised, and managed within OMG's existing governance framework. Specifically, the capability enables an externally authorised position to be:

  • Received into OMG in a structured, auditable form
  • Operationalised as a governed position against a named AI asset
  • Traced end to end, from originating authority through to current status
  • Associated with supporting evidence already held within OMG
  • Monitored for changed conditions affecting continued reliance
  • Routed back to the responsible authority when reassessment or reauthorisation becomes necessary

Following implementation, an independent architecture review of Release 20 identified three findings requiring attention before the capability could be considered complete:

  • External governance state required faithful preservation, without reinterpretation by OMG
  • Scope and applicability required propagation through the full lifecycle, not only at intake
  • Evidence association required a governance-user interface, not only an underlying data model

OMG Release 20.1 addressed all three findings. Validation of both the original capability and the Release 20.1 corrections included: source-code review, production database verification, live API verification, live browser-driven workflow execution, architecture boundary review, and reuse and duplication analysis. This report summarises the resulting implementation and the validation activities performed.

Section 3

Interoperability Lifecycle

The capability is structured as a linear lifecycle. Each stage is described below.

External Authority

A governance position is authorised by a party outside OMG — the originating source of the decision.

↓
Governance Position Intake

The position is received into OMG exactly as authorised — including its source, reference, state, scope, applicability, conditions, and obligations — before any operational action is taken.

↓
Authorised Governance Position

Once accepted, the intake is operationalised as a governed position against a named AI asset, preserving every field captured at intake without modification.

↓
Governance Position Contract

A structured contract is issued from the position, packaging its conditions, obligations, scope, and applicability for downstream reference.

↓
Evidence Association

Existing evidence held within OMG can be linked to the position, connecting the authorised decision to the operational record supporting it.

↓
Changed Condition Detection

OMG's existing governance engines continuously assess whether conditions affecting the position's continued reliance have changed.

↓
Reassessment / Reauthorisation Request

When a changed condition is detected, a reassessment or reauthorisation request is created, recording the reason and the affected position.

↓
Return To Responsible Authority

The request is routed to the accountable authority for the affected asset. OMG records that the matter has been routed; the resulting decision remains with the authority.

Section 6

Governance Boundary Review

The implementation was reviewed to confirm that OMG remains a governance operations capability, and does not become a governance formation capability — that is, OMG operationalises and manages governance positions, but does not create or substitute for the governance judgement of a responsible authority.

Confirmed

✓ No shadow authority model
✓ No shadow accountability model
✓ No parallel governance state engine
✓ No parallel reauthorisation engine
✓ No duplicate governance workflow
✓ No governance decision generation by OMG

Within this boundary, OMG:

  • Preserves governance information exactly as authorised
  • Operationalises governance positions against named assets
  • Associates evidence already held within the platform
  • Detects changed conditions using existing governance engines
  • Routes matters to the responsible authority when action is required

Governance decisions themselves — whether to approve, condition, suspend, or revoke a position — remain with the responsible authority at all times.

Section 8

Release 20.1 Improvements

External Governance State Preservation

External governance state is now captured at intake and preserved without reinterpretation through operationalisation and contracting.

Scope Preservation

Scope now flows through the complete lifecycle — from intake, through the authorised position and its contract, to the traceability view.

Applicability Preservation

Applicability now flows through the complete lifecycle, alongside scope, with the same end-to-end consistency.

Evidence Registry Usability

Evidence association is now available directly through the governance-user interface, in addition to the underlying data model introduced in Release 20.

Section 10

Conclusion

The interoperability capability described in this report has been implemented as a governance-operating capability within OMG. The implementation enables externally authorised governance positions to be received, preserved, operationalised, traced, associated with evidence, monitored for changed conditions, and routed back to responsible authorities when reassessment or reauthorisation is required.

The implementation was reviewed for governance-boundary integrity, architecture reuse, and alignment with the interoperability objectives set out in this report. The final implementation preserves externally authorised governance information without reinterpretation, while maintaining a clear separation between governance operations, which OMG performs, and governance formation, which remains the responsibility of the authorising party.
